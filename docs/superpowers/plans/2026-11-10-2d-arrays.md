# 2D Arrays Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `new Array(r, c)` matrices with `g[i][j]` read/write in Düğüm, drawn as a grid with read/write/ghost marks, shown in C++/Java/Türkçe, plus six lesson pages.

**Architecture:** A matrix is one entry in `allArrays` whose `visual.kind === 'grid'` and whose row arrays are proxied so reads land in `cellReads` as `{visual, index: row * cols + col}` (the same flat index the 1D machinery uses for `read<N>`/`cell<N>` focus edges and `ghosts.cells`). Drawing is a new branch of `drawRowArrays`; the code-language layer learns the two-size declaration in both directions.

**Tech Stack:** PaperScript engine (`js/linkedlist.js`, ES5, no postfix `++` in expressions), PEG.js grammar (`grammer.pegjs` → `npm run build:grammar` → `js/grammar.js`), Playwright tests (`npx playwright test`, server `tests/server.js` port 8765).

**Spec:** `docs/superpowers/specs/2026-11-10-2d-arrays-and-exercises-design.md` (Bölüm 1)

## Global Constraints

- Matrix size: at most 12 rows × 12 columns, each at least 1; invalid → own error `eMatrixSize` (student language, tr/en/de).
- Düğüm stays simple: no jagged/array-of-array (`g[i] = new Array(..)`), no 3D, no nested functions.
- Engine file is PaperScript/ES5: no postfix `++` in expressions, no unary `+`.
- Every page text exists in tr/en/de (`data-lang` blocks, `data-i18n` keys in `js/i18n.js`); code blocks are Düğüm in `<textarea class="deneme">`.
- Every page runs to its end in tr, en, de, Türkçe code, C++ and Java in `tests/pages.spec.js` (`EXPECTED`, `EXPECTED_EN_DE`, `EXPECTED_CPP`, `EXPECTED_JAVA`); the C++/Java views must not contain `var `.
- After every grammar change run `npm run build:grammar` (a test fails when `js/grammar.js` is older).
- Commit footer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>` and `Claude-Session: https://claude.ai/code/session_01GDn6v6g78qdnQxjMjZB9vR`; no model identifier anywhere else.

## Review Focus

- `g[r][c]` with r or c out of range (negative, ≥ size, fractional) must give an own error naming the matrix, the bad index and the valid range, not a JS `TypeError`.
- Reading `g[i]` (a row) without a column, or `g[i][j][k]`, must not crash drawing (row is not a value; student gets the error/expression result like any other).
- A matrix with all-null cells (right after `new Array(3, 4)`) draws an empty grid (crossed cells), not an empty canvas.
- Step back/forward and timeline jumps replay grid state exactly (cells, reads, ghost old values) — `resetVisuals` must clear the grid cells.
- A grid next to 1D arrays (e.g. `dp` matrix plus `a` row) must not overlap: `rowBand` stacks by height.
- Matrix of `true/false` and of numbers wider than 4 characters draws without overflowing the cell (same text sizing as 1D).
